# AGENTS.md - F1 Paddock Guide 專案開發規範

## 1. 專案目的
本專案為「F1 一級方程式賽車主題知識庫」，旨在透過結構化、高可讀性的網頁，介紹 F1 的規則、車隊、車手與經典賽道。本文件定義了網站的視覺風格、檔案結構與擴充規則，確保未來新增任何頁面時，皆能維持高度一致的品質與排版。

## 2. 網頁整體風格與視覺規範
- **主題基調**：現代賽車科技風（Dark Mode 為主），靈感源自 F1 官方轉播介面。
- **色彩系統**（統一寫在 `css/style.css` 的 `:root` 變數中）：
  - 背景主色：`#0f1115`（深炭黑）
  - 卡片底色：`#1a1d24`（深灰藍）
  - 強調主色：`#e10600`（F1 經典賽道紅）
  - 文字主色：`#f3f4f6`（亮灰白），次要文字：`#9ca3af`
- **字體與排版**：無襯線字體（Sans-serif），標題需具備速度感（全大寫英文副標或粗體中文），數據與單圈時間需使用等寬字體（Monospace）對齊。

## 3. 檔案命名與目錄結構規則
所有檔案必須嚴格遵守以下位置與命名規範（全小寫、連字號 `-` 分隔）：
- 根目錄 `index.html`：網站首頁，包含所有子頁面的卡片連結。
- `css/style.css`：全站共用樣式，**禁止在單一 HTML 檔案中寫大量內嵌 `<style>`**。
- `pages/` 資料夾：存放所有內頁，依主題分類加上前綴：
  - 車隊介紹：`pages/team-[車隊英文簡稱].html`（如 `pages/team-ferrari.html`）
  - 規則科普：`pages/rule-[規則主題].html`（如 `pages/rule-drs.html`）

## 4. 新增頁面時的標準結構（HTML 模板規範）
每次新增 `pages/` 下的子頁面時，必須包含以下 4 個區塊：
1. **頂部導覽列 (`<nav>`)**：左側為網站 Logo（點擊返回 `../index.html`），右側為分類選單。
2. **Hero 標題區 (`<header class="page-hero">`)**：包含分類標籤（如 `TEAM PROFILE`）、主標題、副標題，以及 3 個核心關鍵數據卡片（例如：車隊基地、世界冠軍次數、主力動力單元）。
3. **主要內容區 (`<main class="content-container">`)**：使用卡片式分段（歷史沿革、技術亮點、本季焦點），善用表格呈現數據。
4. **頁尾 (`<footer>`)**：版權宣告與返回首頁按鈕。

## 5. AI 協作與修改規則（給 AI 的指令）
當使用者要求「新增一個頁面」或「修改內容」時，AI 必須遵守以下流程：
1. **先讀規範**：建立檔案前，確認檔名符合第 3 點的前綴規則，並引入 `../css/style.css`。
2. **同步更新首頁**：每當在 `pages/` 新增一個 HTML 檔案後，**必須主動在 `index.html` 的對應區塊新增一張導覽卡片（Card）連結至該新頁面**，不可產生孤兒頁面。
3. **保持純淨架構**：僅使用原生 HTML5 與 CSS3，不引入外部大型框架（如 Bootstrap 或 Tailwind CDN），確保 GitHub Pages 載入速度與長期維護性。
